Understanding Git and GitHub.

Git helps developers track changes to their code, while GitHub provides an online place to host repositories and collaborate. Learn what each tool does, where they came from and why they work so well together.

Introduction

Two names you will often hear in software development

Git and GitHub are two commonly used tools in software development. Their names are often mentioned together, but they do not mean the same thing. Understanding the difference makes it easier to see how developers manage projects, preserve earlier versions of their work and collaborate with others.

This article introduces both tools, explains their purposes and shows how they fit into a developer's workflow.

The main idea

Git tracks changes in a project. GitHub is an online platform for hosting Git repositories and working with other developers.

Part 01

What is Git?

Git is a free and open-source Version Control System (VCS) developed by Linus Torvalds in 2005. It allows developers to track changes made to source code over time, save earlier versions and return to those versions when needed.

Why was Git created?

While working on the Linux operating system and its kernel, Linus Torvalds faced the challenge of managing contributions from multiple developers. It was becoming difficult to keep track of changes, identify who had made them and maintain a stable codebase. Git was developed to help solve these version-management problems.

What can Git do?

  • Track changes: keep a record of how source code changes over time.
  • Save versions: use commits to save changes in a local repository.
  • Restore earlier work: return to previous versions when required.
  • Work offline: make commits locally without needing a continuous internet connection.
  • Share later: push local changes to a remote server when an internet connection is available.

Git can be used on Windows, macOS and Linux distributions.

Part 02

What is GitHub?

GitHub is a hosting platform where developers can store their Git repositories online. A repository may look like a project folder, but it also contains the version history tracked by Git.

Developers can push their code to GitHub and fetch or pull changes from remote repositories. The platform also provides tools that make software development and collaboration easier.

What can you use GitHub for?

  • Host repositories: keep project repositories online.
  • Push changes: send local code updates to a remote repository.
  • Fetch or pull changes: retrieve updates from remote repositories.
  • Publish websites: host static websites using GitHub Pages.
  • Collaborate: work on projects with other developers.
  • Track issues: create and follow reports or tasks related to a project.
Remember

A Git repository contains the project's tracked history. GitHub gives you an online place to host that repository and share it with others.

Part 03

Are Git and GitHub the same?

No. Although they are closely related, Git and GitHub have different purposes.

A version control system.An online hosting platform for Git repositories.

One way to remember the difference is to think of Git as a personal assistant that keeps track of changes in your codebase. GitHub is like an online drawer where you can store your repository, keep its records and share it with others.

Conclusion

Different tools, working together

Git manages and tracks your code, while GitHub helps you host and collaborate on it. Git records the development history of a project; GitHub makes repositories easier to store online, access and share.

Knowing the difference between these two tools is a useful first step towards understanding modern software development workflows.
